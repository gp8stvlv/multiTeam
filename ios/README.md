# ГастроГид — iOS MVP

Нативный SwiftUI клиент (iOS 16+) с настоящими запросами URLSession к gateway. Токены сохраняются в Keychain, пароль не сохраняется. Ключ LLM остаётся исключительно на backend.

## Запуск

1. Откройте `GastroGuide/GastroGuide.xcodeproj` в полном Xcode 15 или новее.
2. Выберите общую схему **GastroGuide** и iPhone Simulator. Локальный Swift Package `../GastroAPI` подключён проектом, внешних Swift-зависимостей нет.
3. Для запуска на физическом iPhone задайте свой Development Team в Signing & Capabilities. Bundle ID при необходимости измените.
4. По умолчанию клиент подключается к локальному gateway `http://127.0.0.1:8080/api/v1`, доступному из Simulator. Для другого сервера в экране входа откройте **Изменить адрес API** и укажите доступный gateway с `/api/v1`. Для физического телефона нужен адрес сервера, доступный в его сети: `127.0.0.1` на телефоне означает сам телефон.
5. Зарегистрируйте аккаунт либо войдите в существующий. В **Профиле** задайте вкусы, аллергии, дневной ориентир и бюджет.

Готовый `.xcodeproj` включён в репозиторий; xcodegen не требуется. Проект не включает команду подписи и учётные данные.

Локальный gateway использует HTTP, приватный VPS доступен через SSH-туннель. Для публичного размещения включите HTTPS на сервере, измените URL в приложении и уберите `NSAllowsArbitraryLoads` из `App/Info.plist`. ATS исключение сейчас позволяет подключаться к редактируемому учебному адресу и локальной разработке; UI обозначает HTTP.

## Приватный VPS через SSH-туннель

Удалённый gateway доступен через SSH: проверенное локальное перенаправление на Mac — `127.0.0.1:55080` на `127.0.0.1:8080` VPS. В параметрах SSH это `-L 127.0.0.1:55080:127.0.0.1:8080`; процесс туннеля должен оставаться запущенным. SSH-подключение использует `ubuntu@90.156.213.217`, приватный ключ и проверенный known-hosts с `StrictHostKeyChecking=yes`; команда приведена в корневом README.

В **Изменить адрес API** укажите **`http://127.0.0.1:55080/api/v1`**. Для Swagger в браузере Mac используйте **`http://127.0.0.1:55080/docs/`**. Этот адрес подходит iPhone Simulator на том же Mac. Адрес по умолчанию `http://127.0.0.1:8080/api/v1` остаётся для локального Docker gateway.

Физический iPhone не видит loopback Mac и не сможет воспользоваться таким туннелем через `127.0.0.1`. Для него требуется отдельно настроенный доступный адрес gateway или VPN. Смена URL завершает текущую сессию; аккаунты локального и удалённого backend могут различаться.

Токен GLM будет подключён позже на backend, по инструкции [GLM и OpenRouter](../README.md#glm-и-openrouter). В приложение его вводить не требуется. До настройки провайдера каталог и дневник работают, а подбор показывает серверную ошибку `llm_not_configured`; рекомендации с настоящей моделью ещё не подтверждены.

## Реализованные экраны

- Регистрация и вход; восстановление сессии из Keychain; выход при 401.
- Редактируемый адрес API. Смена адреса завершает сессию, JWT одного сервера не отправляется другому.
- Список ресторанов, актуальное меню, цены в целых копейках, состав, аллергены, источник КБЖУ и фрагменты evidence.
- Подбор блюда или приёма пищи по тексту, бюджету и необязательному лимиту калорий; создание фонового запуска, поллинг с `Retry-After`, остановка ожидания и повторная проверка той же задачи. Повтор отправки использует прежний Idempotency-Key и тот же запрос.
- Результат и уточняющие вопросы, карточки вариантов, причины и предупреждения; чтение персональной ленты.
- Подтверждённое добавление съеденного в дневник с дробной порцией, временем и заметкой; защита повторной отправки через Idempotency-Key.
- Дневник по дате в часовом поясе профиля, дневные КБЖУ, ориентир и остаток; удаление записи после подтверждения.
- Базовый профиль: кухни, нежелательные ингредиенты, острота, коды аллергий, калории, бюджет, часовой пояс, включение персональной ленты.

`null` в КБЖУ отображается как «нет данных». Известная сумма при неполных данных показана отдельно и не выдаётся за полный итог. Пищевая ценность на карточке блюда относится к одной стандартной порции; дневник получает рассчитанный сервером итог съеденного.

## Проверка переносимого API слоя

`GastroAPI` использует Foundation, без SwiftUI или Security. Запросы не содержат `user_id`: идентичность определяется JWT. Decimal нутриенты декодируются из чисел и строк.

В toolchain с XCTest:

```sh
swift test --package-path ios/GastroAPI
```

В macOS окружении только с Command Line Tools без XCTest доступны самостоятельные проверки:

```sh
CLANG_MODULE_CACHE_PATH=/tmp/gastrogid-swift-module-cache \
SWIFTPM_MODULECACHE_OVERRIDE=/tmp/gastrogid-swift-module-cache \
swift run --package-path ios/GastroAPI --disable-sandbox \
  --cache-path /tmp/gastrogid-swift-cache GastroAPIChecks
```

Это 10 групп проверок модели и сетевых запросов через URLProtocol: ограничения URL, null/Decimal, точные копейки, очистка целей профиля, отсутствие JWT в login, дробные порции и idempotency, 202/Retry-After, окончание поллинга при failed, 401 и DELETE 204.

Для интеграции с реально запущенным backend (создаёт тестовый аккаунт и запись, затем удаляет запись):

```sh
GASTRO_API_URL=http://127.0.0.1:8080/api/v1 \
swift run --package-path ios/GastroAPI GastroSmoke
```

Добавьте `GASTRO_SMOKE_RECOMMENDATIONS=1`, чтобы также проверить настоящий запуск и результат агентов. Токены и случайный пароль в вывод не попадают. Успех этой проверки требует реально работающих backend и LLM при включённых рекомендациях.

## Статус проверки

На машине разработки доступны Swift 6.2 и Command Line Tools, полный Xcode и iOS SDK отсутствуют. Foundation package и оба executable собираются; самостоятельные 10 групп API проверок проходят. `swift test` здесь не запускается из-за отсутствующего XCTest. SwiftUI исходники проходят синтаксический разбор, проект и Info.plist — `plutil -lint`.

Живой `GastroSmoke` прошёл против локального gateway `http://127.0.0.1:8080/api/v1` с PostgreSQL: регистрация, JWT профиль, каталог и меню, evidence, добавление половины порции, повтор с тем же ключом без дубля, дневник, дневные итоги, чтение ленты и удаление записи. Реальные рекомендации в этой проверке не запускались: ключ LLM ещё не подключён. Контракт сетевого слоя совпал с фактическими ответами backend.

Полный iOS build, запуск Simulator, Keychain и взаимодействие экранов требуют полного Xcode и остаются отдельной проверкой. Успешный разбор исходников не считается доказательством сборки приложения.

Перечисленный PASS относится к локальному API и переносимому Foundation клиенту. Он не подтверждает доступ с физического iPhone, работу SSH-туннеля из Simulator или результат вызова GLM на VPS.

Минимальный клиент показывает список ресторанов; карта, геолокация, пуши, OAuth и доставка находятся за пределами этого мобильного MVP.
